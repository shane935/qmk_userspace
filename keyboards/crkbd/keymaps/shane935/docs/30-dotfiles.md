# Dotfiles spec (tmux, Claude Code settings, service install)

Read `00-protocol.md` first. Everything here is generated by the daemon's
`--print-*` commands and committed; this spec says what the output must
contain so the dotfiles sandbox can write the install step and tests before
the daemon exists.

## tmux.conf additions

Sourced from the file `kbd-host --print-tmux-conf` generates, committed to
dotfiles. It must contain:

- `set -g focus-events on`
- the root-table bindings from the protocol's tmux key table, one `bind -n`
  per row (`bind -n F13 select-pane -L` …), including the rows marked "bound,
  not sent". Modified rows (`S-F13`, `C-F13`, `M-F13` …) are emitted only when
  the terminal check below passes.
- **no plain key bound in root, ever.** tmux's default root table holds nothing
  but mouse bindings, and `choose-tree` sets no mode key table, so a pane in it
  stays on root and reaches the tree's own keys — arrows, `-`/`+`, `M--`,
  `M-+`, `x`, `Enter` — only because nothing in root matches them first. A
  `bind -n x` would take `x` from choose-tree and the keyboard's TREE layer
  with it. Only F13–F24 and their modified forms belong in root.
- `F20` in `copy-mode-vi` and in `copy-mode`, both to `copy-mode -q`. Belt and
  braces: tmux retries a key in root when the mode table misses it, so the root
  binding alone would fire, but these two lines make "leave whatever mode this
  pane is in" independent of that fallback.
- the WITHIN copy-mode keys in **both** `copy-mode-vi` and `copy-mode`, because
  `mode-keys` decides which table a pane in copy mode uses. The full set is the
  four arrows → `cursor-up`/`-down`/`-left`/`-right`, `PageUp`/`PageDown` →
  `page-up`/`page-down`, `b`/`w` → `previous-word`/`next-word`, `0`/`$` →
  `start-of-line`/`end-of-line`, `/` → `command-prompt -T search -p'(search
  down)' { send -X search-forward -- '%%' }`, `n`/`N` →
  `search-again`/`search-reverse`, `Space` → `begin-selection`, `V` →
  `select-line`, `Escape` → `clear-selection`, `Enter` →
  `copy-pipe-and-cancel`.

  Six of those are already tmux defaults in both tables and are emitted for
  explicitness: the arrows, `PageUp`/`PageDown`, `n` and `N`. The other seven
  are the load-bearing ones, because `copy-mode` is the emacs table and does
  not have them: `b`, `w`, `0`, `$`, `/`, `V` and `Enter` are unbound there,
  and two more are bound to something else entirely — `Space` is `page-down`
  and **`Escape` is `cancel`**. An emacs user without these would page down
  when they meant to start a selection and drop out of copy mode when they
  meant to clear one.

  `Escape` is the one to get right in both tables. `copy-mode-vi`'s own default
  is already `clear-selection`, so binding it to `cancel` would override a
  correct default and break the key for everyone: leaving copy mode is a
  root-table key, which is exactly why `Escape` is free to clear instead.
- `status-right '#{?@kb_os,[#{@kb_os}] ,}#{@kb_mode}#{?@kb_mod, #{@kb_mod},} | %H:%M'`

Nothing here sends to the keyboard; the daemon owns the hooks that do.
A tmux without the daemon still has every root binding, so the keyboard
works prefix-free regardless.

### Terminal check for F13–F24

tmux names F1–F12; F13+ arrive as whatever escape sequence the terminal
emits (xterm-style terminals send F13 as the `S-F1` sequence, which tmux
already names; others need `user-keys[]`). The check, run once per terminal
(Konsole on Bazzite, Terminal.app or the chosen terminal on the Mac):

1. In a tmux pane run `cat -v`, press each of F13–F24 on the keyboard, then
   each with Shift, Ctrl and Alt held. Record the sequences.
2. If tmux names a sequence already (`tmux list-keys` shows it after a
   trial `bind -n`), use that name; otherwise add `set -s user-keys[N]
   "<sequence>"` and bind `UserN`.
3. Any combination that produces no distinct sequence is marked
   unsupported, and its rows are omitted from the generated conf. There is no
   fallback: `ef06ef1365` dropped the firmware's prefix path and the prefix with
   it, so an omitted row is an action the keyboard simply cannot perform on that
   terminal. A terminal that will not pass these keys through is a terminal this
   keyboard does not drive, and the check is how you find that out before
   wondering why a key does nothing.

The result is a per-terminal table committed next to the generated conf.

### Shell integration (OSC 133)

**The keyboard no longer needs this.** It was here so that `{`/`}` on a shell
pane move between commands, and `{`/`}` are not keys the copy column sends: they
belong to the transcript column, where they go to Claude's viewer, and to hunk's
WORD step. Nothing WITHIN sends to tmux copy mode depends on prompt marks. Keep
the section if prompt marks are wanted for their own sake — `previous-prompt` is
still a useful thing to have bound by hand — but it is no longer part of making
this keyboard work, and it can go.

The shell must mark prompts. Add to dotfiles:

- zsh: a `precmd` that prints `\e]133;A\e\\` before the prompt and a
  `preexec` that prints `\e]133;C\e\\` before the command runs (or the
  distro's shell-integration snippet if it already emits these).
- fish: the equivalent in `fish_prompt` / `fish_preexec`, or fish's built-in
  shell integration if the terminal enables it.

Verify with `tmux capture-pane -p -F` on a shell pane: prompt lines carry the
`P` flag and output lines `O`.

## Claude Code hooks

Installed as a Claude Code plugin generated by `kbd-host --print-claude-plugin`
(a `hooks/hooks.json` only), enabled in `~/.claude/settings.json` via
`enabledPlugins`. Every hook is `type: command`, `async: true`, running
`kbd-claude-hook <event>` for: `SessionStart`, `SessionEnd`,
`UserPromptSubmit`, `Stop`, `StopFailure`, `PermissionRequest`,
`Notification` (no matcher), `PostModelSwitch`. The script writes per-pane
tmux user options and nothing else; outside tmux it is a no-op.

This list and the one in `20-daemon.md` are one list. `PostModelSwitch` is here
and not there because it carries no phase — it is a `permission_mode` carrier
only, which the daemon's "from any payload that carries it" rule already covers.
Adding an event to either file means adding it to both.

Because sandboxed agents run with their own `~/.claude`, these hooks apply
to the **host-side** Claude only; the sandbox's Claude is reached through
the same tmux pane and reports nothing. Decide with Shane whether the
sandbox image should carry the same plugin (it would need `tmux` on the
sandbox's PATH talking to the host socket, which it does not have); default
no, in which case the daemon classifies that pane by `pane_current_command`.

## Service

- Linux: udev rule for the keyboard's VID/PID with usage page `0xFF60`
  granting the user's group read/write (`uaccess` tag); a systemd user unit
  `kbd-host.service`, `Restart=always`, `After=graphical-session.target`.
- macOS: a launchd user agent, `KeepAlive`, `RunAtLoad`.
- Both: the daemon binary via mise/npm as the rest of the toolchain; port
  and VID/PID in `~/.config/kbd-host/config.json`.

## Acceptance

- `tmux -f <generated conf> new -d` starts and `status-right` renders empty
  user options without error.
- `tmux list-keys -T root` after sourcing shows every row of the protocol's
  tmux key table, and no plain key: every binding it adds is F13–F24 or a
  modified form of one.
- `list-keys -T copy-mode-vi` and `list-keys -T copy-mode` both show the whole
  WITHIN set, including `F20`.
- `Escape` resolves to `clear-selection` in both mode tables and to `cancel` in
  neither. Worth its own scenario rather than folding into the one above: it is
  the binding whose default differs between the two tables, so it is the one a
  conf generated from the wrong list gets wrong.
- Sourcing the conf into a tmux with `mode-keys emacs` leaves the WITHIN set
  behaving identically to `mode-keys vi` — the point of binding both tables.
- With the shell integration loaded, if it is kept, `capture-pane -p -F` on a
  pane that has run two commands shows two `P` lines.
- Enabling the plugin adds one `enabledPlugins` entry to settings.json and
  leaves existing hooks untouched (fixture with a `PreToolUse` hook).
- The udev rule installs, and `udevadm test` on the device path shows the
  tag.
- The unit starts, restarts after being killed, and logs "waiting for
  keyboard" with nothing plugged in.
