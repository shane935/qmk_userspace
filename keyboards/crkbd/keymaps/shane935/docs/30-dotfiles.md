# Dotfiles spec (tmux, Claude Code settings, service install)

Read `00-protocol.md` first. Everything here is generated by the daemon's
`--print-*` commands and committed; this spec says what the output must
contain so the dotfiles sandbox can write the install step and tests before
the daemon exists.

## tmux.conf additions

Sourced from the file `kbd-host --print-tmux-conf` generates, committed to
dotfiles. It must contain:

- `set -g focus-events on`
- the root-table bindings from the protocol's tmux key table, one `bind -n`
  per row (`bind -n F13 select-pane -L` …). Modified rows (`S-F13`, `C-F13`,
  `M-F13` …) are emitted only when the terminal check below passes.
- `copy-mode-vi` bindings for the WITHIN keys: `{` → `send-keys -X
  previous-prompt`, `}` → `next-prompt`, `C-u`/`C-d` → `halfpage-up/down`,
  `b`/`Space` → `page-up/down`, `/` → `command-prompt -i … search-forward-incremental`,
  `n`/`N` → `search-again`/`search-reverse`, `Escape` → `cancel`.
- `status-right '#{?@kb_os,[#{@kb_os}] ,}#{@kb_mode}#{?@kb_mod, #{@kb_mod},} | %H:%M'`

Nothing here sends to the keyboard; the daemon owns the hooks that do.
A tmux without the daemon still has every root binding, so the keyboard
works prefix-free regardless.

### Terminal check for F13–F24

tmux names F1–F12; F13+ arrive as whatever escape sequence the terminal
emits (xterm-style terminals send F13 as the `S-F1` sequence, which tmux
already names; others need `user-keys[]`). The check, run once per terminal
(Konsole on Bazzite, Terminal.app or the chosen terminal on the Mac):

1. In a tmux pane run `cat -v`, press each of F13–F24 on the keyboard, then
   each with Shift, Ctrl and Alt held. Record the sequences.
2. If tmux names a sequence already (`tmux list-keys` shows it after a
   trial `bind -n`), use that name; otherwise add `set -s user-keys[N]
   "<sequence>"` and bind `UserN`.
3. Any combination that produces no distinct sequence is marked
   unsupported; its rows are omitted from the generated conf and the
   firmware keeps `TMUX_PREFIX_FALLBACK` for those actions only.

The result is a per-terminal table committed next to the generated conf.

### Shell integration (OSC 133)

So that `{`/`}` on a shell pane move between commands, the shell must mark
prompts. Add to dotfiles:

- zsh: a `precmd` that prints `\e]133;A\e\\` before the prompt and a
  `preexec` that prints `\e]133;C\e\\` before the command runs (or the
  distro's shell-integration snippet if it already emits these).
- fish: the equivalent in `fish_prompt` / `fish_preexec`, or fish's built-in
  shell integration if the terminal enables it.

Verify with `tmux capture-pane -p -F` on a shell pane: prompt lines carry the
`P` flag and output lines `O`.

## Claude Code hooks

Installed as a Claude Code plugin generated by `kbd-host --print-claude-plugin`
(a `hooks/hooks.json` only), enabled in `~/.claude/settings.json` via
`enabledPlugins`. Every hook is `type: command`, `async: true`, running
`kbd-claude-hook <event>` for: `SessionStart`, `SessionEnd`,
`UserPromptSubmit`, `Stop`, `StopFailure`, `PermissionRequest`,
`Notification` (no matcher), `PostModelSwitch`. The script writes per-pane
tmux user options and nothing else; outside tmux it is a no-op.

Because sandboxed agents run with their own `~/.claude`, these hooks apply
to the **host-side** Claude only; the sandbox's Claude is reached through
the same tmux pane and reports nothing. Decide with Shane whether the
sandbox image should carry the same plugin (it would need `tmux` on the
sandbox's PATH talking to the host socket, which it does not have); default
no, in which case the daemon classifies that pane by `pane_current_command`.

## Service

- Linux: udev rule for the keyboard's VID/PID with usage page `0xFF60`
  granting the user's group read/write (`uaccess` tag); a systemd user unit
  `kbd-host.service`, `Restart=always`, `After=graphical-session.target`.
- macOS: a launchd user agent, `KeepAlive`, `RunAtLoad`.
- Both: the daemon binary via mise/npm as the rest of the toolchain; port
  and VID/PID in `~/.config/kbd-host/config.json`.

## Acceptance

- `tmux -f <generated conf> new -d` starts and `status-right` renders empty
  user options without error.
- `tmux list-keys -T root` after sourcing shows every row of the protocol's
  tmux key table; `list-keys -T copy-mode-vi` shows the WITHIN bindings.
- With the shell integration loaded, `capture-pane -p -F` on a pane that has
  run two commands shows two `P` lines.
- Enabling the plugin adds one `enabledPlugins` entry to settings.json and
  leaves existing hooks untouched (fixture with a `PreToolUse` hook).
- The udev rule installs, and `udevadm test` on the device path shows the
  tag.
- The unit starts, restarts after being killed, and logs "waiting for
  keyboard" with nothing plugged in.
